# 工作回顧：Fugle → 富邦快照遷移

> 日期：2026-06-22 ～ 06-23
> 主題：把即時股價來源從 Fugle 逐支 quote 改為富邦 `fubon_neo` snapshot，更新頻率 5 分鐘 → 1 分鐘。

---

## 1. 我們要解決的問題

- **舊架構痛點**：Fugle 免費版限流 60 次/分鐘、一支股票打一次 API。為了量開了多把金鑰＋三層備援重試，**仍會漏股**，且被限流綁住只能 5 分鐘一輪。
- **新方案**：富邦 300 次/分鐘，且有 **snapshot 快照**可一次抓回整個市場別的所有股票。一輪只需幾次呼叫 → 不再漏股、可縮短到 1 分鐘。

---

## 2. 今天的決策（共識）

| 主題 | 決定 |
|---|---|
| 開新專案 vs 沿用 | **沿用同專案**，靠 `PRICE_SOURCE` 開關切換 `fubon`/`fugle`；舊 Fugle 程式完整保留當退路 |
| 更新頻率 | 5 分鐘 → **1 分鐘**（`CORE_LOOP_DURATION_SECONDS=60`） |
| 新聞爬蟲 | 目前有問題、維持不變，但與股價**解耦**成最多每 5 分鐘跑一次 |
| 顏色/漲跌幅 | 直接取自快照（`base_price = lastPrice - change`、`changePercent`），不再依賴 `df_base_data.json` 自算 |
| 只寫有變動的 | 加 **分鐘級去重**：與上一輪同價就跳過，省 Notion 流量 |
| 驗證方式 | 採 **evaluator-optimizer loop**：實作完由獨立 context（subagent / 另開 session）對照驗收清單把關 |

## 5. 測試時發現的關鍵 Bug 與修正

### 現象
盤後測試跑 V4，log 出現大量
`[富邦] 快照中查無 8487（可能非上市/已下市），跳過。`
監控 1287 檔中有 **21 個代碼查無**。

### 根因
快照只查了 `market='TSE'`（上市），但：
- **18 檔在「台灣創新板（TIB）」**——如 8487 愛爾達**-創**。創新板雖屬上市大範疇，富邦快照卻把它獨立成 `market='TIB'`，跟 TSE 分開。只查 TSE 會全數漏掉。
- **3 檔（02001R、1589、2380）**全市場別都查不到 → 真正的下市/過期資料。

各市場別實測筆數：`TSE 1526 / OTC 1413 / ESB 355 / TIB 28 / PSB 0`。

### 修正
- `_fetch_snapshot_lookup` 改為**逐市場別查詢並合併**，預設涵蓋 `TSE,OTC,ESB,TIB`（可 .env 覆寫）。單一板失敗只略過該板。
- 結果：原 21 檔查無 → **剩 3 檔**（18 檔創新板全部救回）。
- 3 檔下市股：列清單確認後，**由本人手動清理完成**。

### 教訓
「上市」在富邦快照 API 不等於單一 `TSE`；創新板/上櫃/興櫃各自獨立市場別，需分別查詢合併。先前「只在乎上市＝只查 TSE」的假設不成立。
