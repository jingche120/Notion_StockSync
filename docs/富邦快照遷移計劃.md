# 富邦快照（Snapshot）遷移計劃與驗收文件

> 建立日期：2026-06-22
> 目的：把即時股價來源從 Fugle（逐支 quote、受 60/min 限流、需多帳號、仍會漏股）
> 改為富邦 `fubon_neo` 的 **snapshot 一次抓全上市**，並把更新頻率從 5 分鐘縮短到 1 分鐘。

---

## 0. 背景與目標

### 痛點（現況）
- Fugle 免費版限流：每帳號 60 次/分鐘，一支股票打一次 API。
- 為了量，開了多把金鑰 + 三層備援重試（`STOCK_API_KEYS` → `RESERVE_*` → `LATEST_CHANCE_*`）。
- 即使如此，每輪仍可能有部分股票沒抓到/沒更新。
- 受限流綁住，核心循環只能 5 分鐘一輪。

### 目標（新方案）
- 改用富邦 `reststock.snapshot.quotes(market='TSE')`：**一次呼叫拿回全部上市股票**（實測約 1526 筆）。
- 富邦額度 300 次/分鐘；一輪只需 1 次快照呼叫 → 流量不再是瓶頸、不再漏股。
- 更新頻率 5 分鐘 → **1 分鐘**。
- 只更新「跟上一分鐘相比有跳動」的股票，省 Notion 流量。

### 已對齊的共識
1. 只在乎**上市（TSE）**，`market='TSE'` 一次搞定。
2. **不開新專案、不寫新 main**；用既有的 `PRICE_SOURCE` 開關切換：
   - `.env` 設 `PRICE_SOURCE=fubon` → 走富邦快照
   - `.env` 設 `PRICE_SOURCE=fugle` → 走舊的 Fugle 逐支抓（**舊碼完整保留，當備份/退路**）
3. 新聞爬蟲目前有問題 → **維持不變**，但改成每 5 分鐘才跑一次（與 1 分鐘股價更新解耦）。
4. 下游邏輯（Notion 更新、VIP/VVIP、email、到價判斷）**全部不變**，只換「股價來源」。
5. 顏色/漲跌幅直接採用快照欄位，不再依賴 `df_base_data.json` 自算前日收盤。
6. 第一輪可能略超過 60 秒（開盤幾乎所有股票相對昨收都有變動），可接受。

## 2. 富邦快照資料格式（實測，來自 test0622.py）

`reststock.snapshot.quotes(market='TSE')` 回傳 `dict`，keys：`date`、`time`、`market`、`data`。
`data` 是 list，每檔一個 dict，例如：

```json
{
  "type": "EQUITY", "symbol": "00400A", "name": "主動國泰動能高息",
  "openPrice": 15.55, "highPrice": 15.68, "lowPrice": 15.53, "closePrice": 15.57,
  "change": 0.45, "changePercent": 2.98,
  "tradeVolume": 72658, "tradeValue": 1134847970,
  "lastPrice": 15.57, "lastUpdated": 1782106200000000
}
```

對應到我們需要的：
- 現價 `current_price` = `lastPrice`
- 昨收 `base_price` = `lastPrice - change`（用來決定紅綠、且不再需要 `df_base_data.json`）
- 漲跌幅 `change_percent_raw` = `changePercent`
- 顏色：`change > 0` 紅（RED）、`change < 0` 綠（GREEN）

## 3. 施工項目（Tasks）

> 原則：只新增/修改下列項目，**不動 `workers/api_worker.py`、`utils/task_builder.py`、`workers/notion_worker.py`、新聞下游邏輯**。

### Task 1：新增 `workers/fubon_producer.py`（核心）
實作 `produce_with_fubon(task_q, master_vip_list, master_normal_list, base_data, vip_database_dataframe_dist, api_notion_failure_q)`：

1. **登入一次、重用連線**：module 層級單例。第一次呼叫時 `FubonSDK().login(account, password, cert_path)` + `init_realtime()`，之後每輪重用同一 session（**不每輪重登**）。登入失敗要丟明確錯誤並記 log。
2. 每輪呼叫 `snapshot.quotes(market='TSE')`，把 `data` 串成 `{symbol: item}` 查表。
3. 依序處理 VIP 清單（優先）→ 普通清單，每支：
   - 查表取 `lastPrice`、`change`、`changePercent`。
   - **分鐘級去重**：與「上一輪該股 `lastPrice`」比較，相同就 skip（不丟佇列）。用 module 層級 `_last_price_seen` dict 跨輪保存。
   - 否則計算 `base_price = lastPrice - change`，呼叫 `build_task_packet(...)` 丟進 `task_q`，並更新 `_last_price_seen`。
   - 查不到的股票 → 收進 local 失敗清單。
4. 結束時把失敗清單丟 `api_notion_failure_q`（沿用既有失敗回報機制）。
5. **單執行緒、無節流**（不需要 `FETCH_INTERVAL_SECONDS`）。

### Task 2：`utils/config.py` 接富邦憑證
新增從環境變數讀取：
- `FUBON_ACCOUNT`
- `FUBON_PASSWORD`
- `FUBON_CERT_PATH`（預設可指向 `information/client.pfx`）

### Task 3：`.env` 設定
新增三個富邦憑證變數，並開啟切換：
```

FUBON_ACCOUNT=...
FUBON_PASSWORD=...
FUBON_CERT_PATH=information/client.pfx
```
（`.env` 已被 gitignore，不進版控。）

### Task 4：頻率 5 分鐘 → 1 分鐘，新聞解耦
- `utils/config.py`：`CORE_LOOP_DURATION_SECONDS` 由 `300` → `60`。
- `main.py` 的 `run_5_minute_core_loop`：新聞爬蟲改成「距離上次爬取 ≥ 5 分鐘才跑」，不再每輪都跑。
  （函式名稱可保留，避免牽動太多；或加註解說明已變成 1 分鐘循環。）

### Task 5：安裝與文件

## 5. 風險與備註

- **每輪重登富邦會被限流**：務必登入一次、重用 session。
- **第一輪偏慢**：開盤第一輪相對昨收幾乎全變動，Notion 寫入量大、可能 > 60 秒；之後恢復正常。不可接受時加 `NOTION_API_KEY_LIST` 金鑰。
- **`df_base_data.json`**：本次改造後，顏色/漲跌幅不再依賴它；但盤後更新它的流程**先保留**，待穩定後再決定是否退役。
- **盤後/盤前**：市場狀態機（PRE/IN/POST_MARKET）維持原樣，盤中才真正更新。
- **憑證安全**：帳密與 `.pfx` 路徑改由 `.env` 提供，不再寫死在程式碼（`test0622.py` 的寫死寫法不沿用）。
- **⚠️ 測試開關 `SIMULATE_PRICE_CHANGE` 上線前必須關閉**：此開關（`.env`）開啟時，富邦路會讓每檔 `lastPrice` 各有 0.5 機率 +1，用來在盤後測試 1 分鐘更新與去重。**正式上線前務必把 `.env` 的 `SIMULATE_PRICE_CHANGE` 設為 `false` 或移除**，否則會把假價格寫進 Notion。預設為 false，只有 .env 明確設 `true` 才啟用。
